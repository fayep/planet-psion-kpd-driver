# Cosmo Communicator — Gemian Linux Setup

**Tested on**: Cosmo Communicator running Gemian Linux (kernel 4.4.146)

---

## Why a custom driver is needed

The Gemian 4.4 kernel ships with `CONFIG_MTK_AW9523=y` — the Android AW9523B keyboard
driver compiled directly into the kernel.  This driver registers as both a platform driver
and an I2C driver named **"Integrated keyboard"**.  It works for basic keyboard input but:

- It does not expose the Fn/Meta function layer correctly for Linux xkb
- It maps the physical key positions to Android-era keycodes that do not match the xkb
  layout in `userspace/xkb/planet_vndr/cosmo`
- Power/ESC and voice command buttons are routed to the Android LXC container and are
  not visible to the Linux desktop

The `planet_kpd` module replaces "Integrated keyboard" with a correctly-mapped Linux
input device and enables the full xkb Fn layer.

## Prerequisites

```bash
sudo apt-get install linux-headers-$(uname -r) build-essential xbindkeys
```

---

## Build the module

```bash
git clone https://github.com/fayep/planet-psion-kpd-driver
cd planet-psion-kpd-driver/kernel
make
```

Copy the built module somewhere permanent:

```bash
cp planet_kpd.ko ~/planet_kpd/planet_kpd.ko
```

---

## Load the module (manual, first test)

The built-in "Integrated keyboard" I2C driver must be unbound before our module can
probe the AW9523B.  **Do not unbind the platform device** (`/sys/bus/platform/drivers/aw9523_key/`);
only unbind the I2C driver as shown below.  Unbinding the platform device leaves a
dangling EINT handler that causes a kernel panic on the next keypress.

```bash
# Unbind the built-in I2C driver from the AW9523B
echo 4-005b | sudo tee "/sys/bus/i2c/drivers/Integrated keyboard/unbind"

# Load our module
sudo insmod ~/planet_kpd/planet_kpd.ko
```

Confirm it worked:

```bash
dmesg | grep planet_kpd
# Expected: planet_kpd 4-005b: AW9523B keyboard ready (polling mode)

grep "Planet keyboard" /proc/bus/input/devices
# Expected: N: Name="Planet keyboard"
```

## Make it persistent (systemd)

```bash
sudo tee /etc/systemd/system/planet-kpd.service << 'EOF'
[Unit]
Description=Planet Computers AW9523B keyboard driver
After=multi-user.target

[Service]
Type=oneshot
ExecStart=/bin/sh -c 'echo 4-005b > "/sys/bus/i2c/drivers/Integrated keyboard/unbind" && insmod /home/cosmo/planet_kpd/planet_kpd.ko'
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl enable planet-kpd.service
sudo systemctl start planet-kpd.service
```

## xkb keyboard layout

The correct xkb layout is at `userspace/xkb/planet_vndr/cosmo`.  Install it:

```bash
sudo cp userspace/xkb/planet_vndr/cosmo /usr/share/X11/xkb/symbols/planet_vndr/cosmo
setxkbmap -layout "planet_vndr/cosmo" -variant us -option lv3:lwin_switch
```

To persist across reboots, edit `/etc/default/keyboard`:

```
XKBMODEL="pc105"
XKBLAYOUT="planet_vndr/cosmo"
XKBVARIANT="us"
XKBOPTIONS="lv3:lwin_switch"
BACKSPACE="guess"
```

### Fn layer (Meta key)

| Key combo    | Action              |
|-------------|---------------------|
| Meta+Q       | Play/pause          |
| Meta+W       | Previous track      |
| Meta+E       | Next track          |
| Meta+R       | Screenshot (Print)  |
| Meta+T       | Mic mute            |
| Meta+A       | Task pane           |
| Meta+D       | Top menu            |
| Meta+F       | RF kill / Wi-Fi toggle |
| Meta+C       | Volume down         |
| Meta+V       | Volume up           |
| Meta+B       | Brightness down     |
| Meta+N       | Brightness up       |
| Meta+BS      | **Escape** (no physical ESC key — see note below) |
| Meta+Space   | Voice record        |
| Meta+Left    | Home                |
| Meta+Up      | Page up             |
| Meta+Down    | Page down           |
| Meta+Right   | End                 |

**Note on Escape**: The physical power/ESC button on the Cosmo routes through the PMIC
to the Android LXC container and is not visible to the Linux desktop input layer.
Meta+Backspace is mapped to Escape as a workaround.

## Wi-Fi toggle (Meta+F)

`XF86RFKill` (generated by Meta+F) is not handled reliably by urfkill on the Cosmo 4.4
kernel.  Instead, xbindkeys is used to call a toggle script directly.

Install files from `userspace/cosmo/`:

```bash
mkdir -p ~/bin
cp userspace/cosmo/scripts/toggle-wifi.sh ~/bin/toggle-wifi.sh
chmod +x ~/bin/toggle-wifi.sh

# Note: bind to Mod5+f (explicit modifier), NOT XF86RFKill keysym —
# xbindkeys falls back to AnyModifier for level-3 keysyms and will
# trigger on plain 'f' if you use the keysym form.
cp userspace/cosmo/autostart/xbindkeysrc ~/.xbindkeysrc
xbindkeys

# Autostart on login
mkdir -p ~/.config/autostart
cp userspace/cosmo/autostart/xbindkeys.desktop ~/.config/autostart/
```

## Shutdown

**Use software shutdown** (`sudo shutdown -h now` or the KDE session menu).

With the built-in "Integrated keyboard" driver, holding the power button raises KDE's
shutdown dialog.  Our module breaks this: unbinding "Integrated keyboard" removes the
virtual input device that the built-in platform driver uses to forward KEY_POWER to
logind.  Without it, a long press goes directly to the Android LXC container which
performs a hard power-off, bypassing the Linux shutdown sequence.

The proper fix is to access the AW9523B via raw I2C (grabbing the adapter directly via
`i2c_get_adapter(4)` rather than registering an `i2c_driver`), so that "Integrated
keyboard" stays alive for the power button while our module handles the QWERTY matrix.
This is planned for a future revision.

## Known limitations (Cosmo / 4.4 kernel)

- **Interrupt mode unavailable**: The built-in aw9523_key driver registers IRQ 31
  (`aw9523-eint`) at kernel init time without `IRQF_SHARED`.  Our module falls back to
  10 ms polling, which is sufficient for keyboard use.
- **Power/ESC button**: Not reachable from Linux desktop; goes to Android LXC container.
  Meta+Backspace is the Escape workaround.
- **Volume buttons**: Mapped to mouse buttons by the STM32 companion chip driver
  (`stm32_key`); unrelated to this module.
- **Back screen (CoDi) trackpad**: Managed by `codiServer.py` and the STM32 driver;
  unrelated to this module.
